# ERP RH & DP — FC Engenharia

A comprehensive full-stack ERP system for FC Engenharia, managing HR, payroll, projects, finance, procurement, and operational workflows.

## Run & Operate

- **Dev**: `PORT=5000 NODE_ENV=development pnpm dev`
- **Build**: `pnpm build`
- **Prod**: `node dist/index.js`

**Required Env Vars**:
- `NEON_DATABASE_URL` (or `DATABASE_URL`)
- `JWT_SECRET` (random 48-char hex)
- `NODE_ENV=production`
- `SMTP_PASSWORD`
- `GOOGLE_API_KEY`
- `FROTA_API_TOKEN` (for Infleet API)
- `VITE_APP_TITLE`
- `VITE_APP_LOGO`
- `OAUTH_SERVER_URL`
- `VITE_APP_ID`
- `OWNER_OPEN_ID`

## Stack

- **Frontend**: React 19, Tailwind CSS 4, shadcn/ui, Wouter
- **Backend**: Express 4, tRPC 11, Drizzle ORM
- **Database**: PostgreSQL (Neon)
- **Auth**: Manus OAuth (JWT) or local username/password
- **Build**: Vite 7
- **Package Manager**: pnpm

## Where things live

- `client/`: React frontend
- `server/`: Express backend + tRPC routers
  - `server/_core/`: Auth, OAuth, Vite setup, env config
  - `server/routers/`: tRPC routers per módulo
  - `server/db.ts`: Database helpers
- `drizzle/`: Schema and migrations
- `shared/`: Shared types and constants (`shared/version.ts`, `shared/changelog.ts`, `shared/paymentConditions.ts`, `shared/modules.ts`)
- **DB Schema**: `drizzle/schema.ts`
- **API Contracts**: tRPC routers in `server/routers/`
- **Theme/UI**: `client/src/index.css`, `tailwind.config.ts`, `shadcn/ui` components

- **Rev. 2050**: **SST · Integração · AUTO-MIGRAÇÃO no startup das 12 perguntas-padrão "Regras de Ouro" da Rev. 2047 — corrige tenants com seed antigo da Rev. 2046 (NRs/capacete) OU com perguntas duplicadas do próprio seed novo.** Pedido direto do usuário (IMG_0936): "As perguntas não tem nada a ver com o vídeo, melhore isso.. quero que as regras de ouro estejam no questionário". **Investigação**: código já tinha as 12 perguntas certas (`PERGUNTAS_REGRAS_OURO` Rev. 2047); o DB do FC (company=60002, módulo=1) tinha **24 perguntas duplicadas** (pid 13-24 + pid 25-36, mesma ordem 1-12 repetida 2x) — alguém clicou "Carregar Regras de Ouro" 2x antes do fluxo "Substituir" da Rev. 2047 existir. O screenshot IMG_0936 era de uma sessão anterior ainda no seed Rev. 2046. **Solução em 2 arquivos (zero schema/contrato)**: (A) `server/routers/integracaoSST.ts` — `PERGUNTAS_REGRAS_OURO` passa a ser `export` (antes era módulo-local) pra reuso no startup. (B) `server/_core/index.ts` — novo bloco one-shot pós "[SyncSchema+] Tabelas SST Integração garantidas": CTE `stats` calcula por módulo `total` (COUNT perguntas), `tem_antigo` (ILIKE em 4 âncoras NR Rev. 2046: capacete+óculos+botina, cinto de segurança, espaço confinado, fio elétrico desencapado), `canonicos` (COUNT perguntas cujo texto está em PERGUNTAS_REGRAS_OURO), `texts_distinct` (COUNT DISTINCT texto). Filtra módulos stale: `tem_antigo>0` OU `canonicos>0 AND total>texts_distinct` (tem canônicos + duplicatas, caso FC) OU `canonicos>0 AND total≠12` (canônicos mas qtd errada). Pra cada stale, 1 transação atômica: DELETE alternativas WHERE pergunta_id IN (módulo) → DELETE perguntas WHERE id IN (módulo) → INSERT das 12 perguntas + 36 alternativas (ordem preservada). **Safeguards**: idempotente (após 1ª execução, filtro não casa de novo — validado: módulo migrado, restart subsequente não detecta nada); módulos CUSTOMIZADOS sem nenhuma canônica (`canonicos=0`) só disparam se tiverem seed antigo; cross-tenant (WHERE moduloId+companyId em todo DELETE/INSERT); respostas históricas em `sst_integracao_respostas` NÃO afetadas (sem FK rígida, design Rev. 2034); try/catch externo + try/catch por módulo. **Resultado produção**: `m=1 c=60002 total=24 distinct=12 canonicos=24 tem_antigo=0 → re-seed com 12 limpas`. **Por que não dedupe in-place**: as 24 tinham mesma `ordem` 1-12 repetida 2x — escolher qual `pergunta_id` manter por (modulo,ordem) é arbitrário e arrisca invalidar respostas históricas; wipe-and-reseed é mais simples e zera drift de texto/alternativa. + `shared/version.ts` → 2050. **R-001/R-007/R-010 OK**: ZERO ALTER/DROP de SCHEMA; o DELETE roda em SEED (não dados do usuário) em transação atômica e só em módulos stale. **Preservado**: Rev. 2049/2048/2047/2046/2045/2044 INTACTAS; handler manual `semearPerguntasPadrao` (botão "🔄 Atualizar Regras de Ouro") INTACTO; constante `PERGUNTAS_REGRAS_OURO` só ganhou keyword `export`. **Follow-up**: (1) opt-in por config quando virar multi-tenant; (2) versionar `PERGUNTAS_REGRAS_OURO` com hash e disparar migração só quando mudar; (3) banco de perguntas reutilizável mantido pelo admin_master via UI; (4) embaralhar ordem das alternativas na tela pública.
